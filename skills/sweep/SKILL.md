# Sweep earlier sessions for anything left behind

Run it when the user asks for a sweep, or takes the one a track's finish or drop offers. The verb and the reader only read; you file the homes, and the user decides what only they can.

1. **Scope.** The user's words name it: a track (`TR-n`) runs `node ~/.claude/askerdo/cli.mjs sweep --track TR-n`, its sessions as the board records them; "since the last sweep" runs `sweep --since-last`; a day runs `sweep --since YYYY-MM-DD`. Run it from the project's folder. With no scope named, ask which. On a PC with no earlier sweep of the project, `--since-last` says so: ask the user for a day.
2. **The verb.** It writes, under this PC's data folder and never in the repo or on the board: a digest per session (copied turns left out), `candidates.md` (every message the user typed, and the reply lines that name something left), `board-scan.md` (closed tasks whose last note names something left, inbox tasks woken with no home) and `brief.md`, the reader's brief. It prints the folder and the counts. With nothing digested and nothing in the board scan, tell the user so and stop.
3. **The reader.** Dispatch one agent on the explicit opus model, prompted to read `<folder>/brief.md` and follow it: read only, writing nothing, its report its final response. Do not read the digests yourself, and never end your turn to wait for it.
4. **Homes.** For each LOST and FILED-STALE item, check its evidence with one read (`show`, `search`, `git log`), then give it the nearest home that comes back on its own, under the found work rule: an open task that covers it takes a `note`; work for the track you hold is filed at once at a real place in its order (`place` tier 2, `task create --tier 2`, with `--after` what it needs and `--before` the open tasks that must not finish without it); anywhere else (last on that track, another track, a parked track an event opens, another workstream or project, an inbox, a later session) is the user's call: file it with the place you want (`--last "<why>"`, or `--tier 3 --track TR-n` or `--unpark-when`, or `--tier 4 --workstream WS-n`, with `--why-elsewhere "<why>"`) and `--here-before`, the real place on your track it would otherwise take (left out when nothing there waits on it), and the board asks the user, creating nothing until their press; what only the user can decide is a question. A ruling the user made in chat goes in a decision, in their words, and a fact in a knowledge record. A refused filing names the call that fits: send it. A closed task's note, a handoff's prose, a state doc, a scratch file or a reply is not a home. An UNSURE item you settle with a read is homed the same way; one you cannot goes in the report. FILED-LIVE and DONE items need nothing.
5. **The user's calls.** Ask the user only what is theirs: a delete (a worktree, a branch, files), a look that may be moot by now, an idea they may no longer want. One question each, with your pick.
6. **Report.** The counts per verdict, each item homed with its new record's id, what waits on the user, and the sweep folder's path.
